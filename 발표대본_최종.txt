안녕하세요. 오늘은 제가 스마트스토어 상품 등록 자동화 시스템을 소개하려고 합니다. 

2. 기획 단계별 흐름

첫날에는 금시세 카톡 알림앱을 만들어서 자동화를 연습했는데 프로젝트로 하기엔 너무 간단해서 주제를 바꿨습니다. 네이버 스마트스토어 커머스 API를 발급 받는 쪽으로 다시 생각해서 스마트 스토어에 상품 등록 해주는 앱을 일단 만들어 봤습니다.  2일차에는 만든 앱에 자동화 시스템을 입혀보고자 설계 프롬프트를 쓰고, 9단계로 나눠서 순서대로 구현해 실행 파일과 사용법까지 만들었습니다.  3일차에는 앱을 직접 써 보면서 실제로 상품을 등록해보고, 부족한 기능을 보완하고, 실제 상품을 판매까지 해 보았습니다.

3. 먼저 정한 세 가지 질문

무엇을 만들지 정하기 전에 세 가지를 먼저 물었습니다. 누가 쓸 것인가, 그 사람은 무엇을 어려워하는가, 그리고 우리 서비스로 무엇을 더 쉽게 끝낼 수 있는가입니다. 제 답은 스마트스토어 창업을 계획하는 분들이었고, 그분들에게 상품 등록 절차가 너무 복잡하다는 점이었습니다. 그래서 목표를 이렇게 잡았습니다. 사람은 판단이 필요한 정보만 입력하고, 사진 처리부터 상품명, 상세페이지, 등록, 결과 보고까지는 자동으로 처리해서 시간을 아끼자는 것입니다.

2부 DAY 1 — 상품 등록 앱 만들기 (4~7)

4. DAY 1 

5. 스마트스토어 생성과 커머스 API 발급

일단은 스마트스토어가 개설 되어 있어야 구현이 될지 말지도 정해지겠죠? 그래서 스마트스토어부터 개설했고

앱이 스마트스토어와 연결되려면 네이버 커머스 API가 필요합니다.  커머스API센터에 판매자 계정으로 로그인하고, 애플리케이션을 등록해 사용할 API와 호출 IP를 정했습니다. [화면] 그러면 이렇게 애플리케이션 ID와 시크릿이 발급됩니다. 중요한 점은 이 시크릿을 코드나 파일에 적지 않고 Windows 자격 증명 관리자에만 보관했다는 것입니다.

6. 앱 설계 프롬프트: 화면 · 구조 · 순서

AI에게 바로 코드를 시키지 않고 설계도부터 정리했습니다. 화면은 상품 등록, 엑셀 일괄 등록, 상품 관리, 템플릿, 설정으로 나누었고, 폴더 구조도 역할별로 정했습니다. 개발은 여섯 단계로 나눠 단계마다 '확인 방법'을 붙였습니다. 예를 들어 2단계는 '스마트스토어에 실제로 등록되는지'를 확인해야 다음으로 넘어갔습니다.

7. 완성된 상품 등록 앱

결과물입니다. [화면] 상품명과 판매가, 재고를 입력하고 카테고리를 검색해서 고르고, 이미지는 끌어다 넣으면 됩니다. 색상과 사이즈 조합형 옵션도 만들 수 있습니다. 하지만 상품마다 사진 정리부터 상세페이지까지는 여전히 손으로 해야 했고, 그걸 해결하고자 자동화 시스템을 생각합니다.

3부 DAY 2 — 자동화 설계 (8~11)

8. DAY 2 제목

9. 상품 등록 과정에서 자동화가 필요한 부분 생각해보기

먼저 상품이 들어오는 길을 두 가지로 정했습니다. 도매몰에서 사입하는 경우는 엑셀에 정보를 넣고 도매몰 이미지를 쓰고, 직접 촬영하는 경우는 폰 사진이 클라우드로 PC 폴더에 들어옵니다. [화면] 아래는 상품 등록 과정의 전체 흐름입니다. 사진 정리와 보정, AI 초안, 검증, 상세페이지 조립을 거쳐 등록하고 결과를 알려줍니다. 핵심은 마지막 칸입니다. 등록은 항상 판매중지로 하고, 사람이 검수한 뒤에야 판매를 시작합니다.

10. 만들기 전에 정한 규칙 5가지

실제 스토어와 돈이 걸린 일이라 안전 규칙부터 정했습니다. 키와 토큰은 keyring에만 저장하고, 사람이 입력한 값은 자동화가 덮어쓰지 않고, 원본 사진은 절대 건드리지 않습니다. 새 기능마다 테스트를 만들고, 실제 등록 테스트는 판매중지 상태로 한 건씩만 했습니다. 이 규칙 덕분에 나중에 실수가 생겨도 되돌릴 수 있었습니다.

11. 프롬프트 생성: 9단계로 나눠 하나씩 구현

자동화는 한 번에 만들지 않고 아홉 단계로 나눴습니다.  핵심 기능은 엑셀로 등록, 사진 보정,  상세페이지와 검수 부분이고 예약 알림, 판매 흐름, QR 사진 분류와 AI 초안, 실행 파일이 편의 기능입니다. 한 단계가 끝날 때마다 제가 직접 확인하고 다음 단계로 넘어갔습니다.

4부 자동화 9단계 구현 (12~20)

12. 자동화 1단계 — 작업 엑셀과 분류 매핑

모든 자동화의 시작은 엑셀 한 개입니다. 상품 하나가 엑셀 한 줄이고, 상품코드와 원가, 옵션, 분류만 적으면 됩니다. 여성티셔츠, 니트, 스커트 같은 분류 일곱 개를 네이버 카테고리에 미리 연결해 두었고, 분류별 마진율로 판매가도 자동으로 계산됩니다.

이 작업은 앱을 처음 깔았을때 처음에만 하면 되고 그 다음부터는 계속 저장된 그대로 사용하면 됩니다.

13. 자동화 2단계 — 자동 등록과 중복 방지

중요한 내용은 아닌데 그냥 대기상태로 상품등록을 처리해서 등록한다는 얘기에요 넘어갈게요.

엑셀에서 '대기' 상태인 상품만 골라 검증하고, 하루 한도와 중복을 확인한 뒤 등록합니다. 같은 상품이 두 번 올라가지 않도록 엑셀, 앱 기록, 스토어 상품코드까지 세 번 확인합니다. 오류가 나도 다음 상품은 계속 처리하고, 결과는 엑셀에 다시 적힙니다. 이때도 사람이 입력한 칸은 절대 건드리지 않습니다. 

14. 자동화 3단계 — 사진 보정과 배경 제거(누끼따기)

사진은 밝기와 화이트밸런스를 자동으로 맞추고, 대표 이미지는 배경을 지워 흰 배경으로 바꿉니다. 이걸 누끼 딴다고 하는데  중요한 내용은 아닙니다. [화면] 왼쪽은 배경 제거 방식별 결과 비교입니다. 원본은 그대로 두고 보정본은 따로 저장하며, 한 번 보정한 사진은 다시 처리하지 않습니다. 저작권 때문에 2D그림을 예시로 들었지만 어쨌든 보정 된 거 랍니다..

15. 자동화 4단계 — 상세페이지 템플릿 만들기

상세페이지는 공지, 설명, 옵션, 사진, 사이즈, 소재와 세탁, 배송과 교환 순서로 자동 조립됩니다. 엑셀에 적은 값과 사진만 있으면 오른쪽 같은 페이지가 만들어집니다. 분류별로 디자인을 바꿀 수 있고, 등록 전에 브라우저로 미리 볼 수 있습니다.

16. 자동화 5단계 — 사람이 검수한 뒤 판매 시작

자동으로 등록된 상품은 항상 판매중지 상태라 고객에게 보이지 않습니다. 검수 대기 탭에서 썸네일과 상품명, 가격, 상세페이지를 확인하고 '판매 시작'을 눌러야 판매가 시작됩니다. 자동화를 믿되, 마지막 판단은 사람이 하도록 한 것입니다.

17. 자동화 6단계 — 예약 실행과 카카오톡 알림

Windows 작업 스케줄러로 정해진 시각에 자동 등록이 돌고, 결과는 카카오톡 '나에게 보내기'로 받습니다. 재미있는 점은 첫날 금시세 알림을 만들 때 쓴 카카오 알림 앱을 그대로 다시 썼다는 것입니다. 연습 삼아 만든 것이 실제 제품의 부품이 됐습니다.

18. 자동화 7단계 — QR 카드로 사진 자동 분류

여기서부터는 편의 기능이라 중요하진 않습니다. 사진을 여러 상품 분량으로 한꺼번에 찍으면 나중에 나누는 게 일입니다. 그래서 상품코드 QR 카드를 먼저 찍고 이어서 그 상품 사진을 찍도록 했습니다. 폴더에 넣기만 하면 QR을 기준으로 상품별 폴더가 자동으로 나뉘고, 애매한 사진은 '미분류'로 남깁니다.

19. 자동화 8단계 — AI 초안: Claude가 상품명 후보 제안

이건 근데  클로드 토큰이 있어야 가능해서 제 돈주고 한번 해봤는데 이런식으로 해줍니다. 보정한 사진 몇 장과 엑셀 정보를 Claude에게 보내면 상품명 후보 세 개와 특징, 검색 태그, 색상을 제안해 줍니다. [화면] 왼쪽이 상품 목록, 오른쪽이 각각의 제안입니다. AI는 빈 칸만 채우고 사람이 쓴 값은 그대로 둡니다. 비용을 아끼려고 상품마다 한 번만 호출하고 결과를 저장해 둡니다.

20. 자동화 9단계 — 실행 파일과 사용법

마지막으로 다른 컴퓨터에서도 쓸 수 있게 실행 파일로 묶었습니다. 평소에 쓰는 화면 앱, 명령줄 도구, 그리고 창 없이 예약 실행되는 파일까지 세 개입니다. 설치부터 문제 해결까지 담은 사용법 문서도 함께 만들었습니다.

5부 써보며 보완 (21~22)

21. 보완 ① — 써보니 보인 것: 화면 다듬기

만들고 나서 직접 써 보니 불편한 점이 보였습니다. 자동화 설정 화면에 빈 공간이 많아서 왼쪽과 오른쪽 두 단으로 다시 배치했습니다. 알림 창의 글씨와 버튼이 잘리던 문제도 내용에 맞게 폭이 늘어나도록 고쳤습니다.

22. 보완 ② — 배경 제거를 더 깔끔하게

가장 애먹은 부분은 배경 제거였습니다. 흰 티셔츠 가장자리가 지저분하게 남아서 부드러운 마스크를 써 봤는데, 오히려 반투명한 테두리가 생겨 더 나빠졌습니다. 결국 선명한 마스크로 돌아가고, 옷 색을 지키면서 가장자리를 한 번만 정리하도록 바꿨습니다. 다만 옷과 배경 색이 같으면 여전히 경계를 구분하기 어렵다는 한계가 있습니다.

6부 DAY 3 — 실사용 (23~37)

23. DAY 3 제목

24. 가상의 상품을 직접 구성해 보기

일단 동대문 도매에서 일하는 친구의  협찬을 받아 실제로 판매하고 있는 상품 사진을 가져왔습니다. 저는 직업이 MD였어서 상품등록할 때 어떤 이미지가 필요한지 알고 빠르게 처리 할 수 있지만, 처음 하시는 분들은 썸네일, 대표이미지, 누끼 이미지로 분류해놓고 준비를 해놓으시면 좋습니다. 상품명, 상품고시 정하는것도  AI한테 물어보면 금방 만들어 줍니다. 공지와 사은품, 행사 내용 이런건 나중에 직접 판매하시면서 익히는 부분이라 넘어가겠습니다.

25. 직접 디자인한 상세페이지(L001) : 클로드로 자동등록

자동화 기능을 통해서 상세페이지를 만들어도 되지만 시간이 좀 남아서 직접 제작해봤습니다. [화면]  L001 꽈배기 니트의 상세페이지입니다. 공지와 사은품  부분은 저렇게 보인다고 보시면 되고요.  완성한 이미지는 '이미지만' 템플릿으로 올리면 이미지 그대로 상세페이지에 들어갑니다.

26. 클로드에게 상품 등록을 시켜보기

일단 앱이 스마트스토어와 연동 되어서 잘 구현 되는지 확인 차 클로드에게 상품 등록을 시켜봤습니다.

 [클릭] 실제 스토어 페이지를 열어 보겠습니다. 잘 올라가 있는 모습 확인 하실 수 있습니다.

27. 사용 가이드 만들기

하지만 모든 사람이 클로드를 쓰는 것은 아닙니다. 그래서 제가 직접 자동화를 돌려 보면서, 누구나 따라 할 수 있는 사용 가이드를 만들었습니다. 두 번째 상품 L002를 앱으로 등록한 과정을 아홉 단계로 보여드리겠습니다.

28. 1. 상품 사진 넣기

자동화 설정에서 '상품 사진 넣기'를 누르고 상품코드를 입력합니다.  사진만 넣으면 알아서 폴더를 생성하고 분류해줍니다. 간단하죠?

29. 2. 작업 엑셀에 상품 입력

다음은 엑셀 한 줄입니다. 이건 같은 엑셀파일을 계속 쓰기 때문에 L001을 등록하면서 미리 작성해놓은 데이터를 참고해서 작성하시면 됩니다.  판매가는 원래는 수수료랑 마진율을 따져서 원가를 입력하면 엑셀 자체에서 계산해주지만 다른 곳이랑 가격 차이가 나지 않게 지정가로 판매해야 하는 경우도 있기 때문에 22,000원으로 지정가로 올리는 부분을 추가했고, 사진은 이미 보정되어 있으니 보정하지 않고, 상세페이지는 만들어논 이미지만 쓰도록 고를 수 있습니다.

30. 3. 검증 미리보기 → 등록

등록 전에 '검증 미리보기'로 오류가 없는지 확인합니다. 문제가 없으면 '대기 상품 처리'를 눌러 판매중지 상태로 등록하고, 결과 창에서 네이버 상품번호까지 확인할 수 있습니다.

31. 4. 카카오톡으로 결과 받기

등록이 끝나면 카톡으로 결과가 옵니다. “등록 1건, 실패 0건, 검수 대기 17건.” 예약 실행으로 돌릴 때도 같은 알림을 받을 수 있어서, 컴퓨터 앞에 없어도 결과를 알 수 있습니다.

32. 5. 검수 대기 탭에서 확인

상품 관리의 검수 대기 탭에 방금 등록한 L002가 판매중지 상태로 뜨고, 썸네일과 상품명, 가격을 한눈에 볼 수 있습니다. '상세보기'를 누르면 상세페이지도 바로 확인할 수 있습니다.

33. 6. 선택 상품 수정

고칠 게 있으면 상품을 체크하고 '선택 상품 수정'을 누릅니다. 상품명, 판매가, 옵션별 재고를 바로 고칠 수 있고, 저장하면 스토어에 곧바로 반영됩니다.

34. 7. 판매 시작과 검색 태그

검수가 끝나면 '판매 시작'을 눌러 판매중으로 바꿉니다. 검색 태그는 중요한 내용은 아닙니다.  아직 앱에서 구현이 안된 기능이라 차 후에 업데이트 해보려고 합니다.

35. 8. 스토어에서 확인

잘 올라갔는지 확인해 줍니다. 잘 올라갔네요.

36. 9. 판매 상태 관리

판매를 시작한 뒤에도 앱에서 상태를 관리합니다. 판매중지, 판매중, 품절로 바꿀 수 있는데, 품절은 재고를 0으로 만드는 방식입니다. 다시 팔 때는 수정 창에서 재고만 넣으면 판매중으로 돌아옵니다.

37. 10. 결과물: 실제 스토어 상품 페이지

이렇게 등록한 상품이 실제 스토어에 올라간 모습입니다.  품절 처리 해놓아서 품절로 되어있는 것 까지 반영이 잘 되어 있는 것을 확인할 수 있습니다. 

7부 마무리 (38~42)

38. 보완 ③ — 더 편하게: 수정과 사진 넣기

이건 자동화 기능을 통해 실제로 상품등록을 해보면서 추가하거나 개선한 부분입니다. 앱 내에서 상품명과 판매가, 옵션별 재고를 바로 고치는 기능을 추가했고,  원래 사진 넣을때 따로 폴더를 생성해서 하나씩 넣어야 했는데 앱 내에 그냥 사진 넣기 탭을 만들었습니다.  만들다 보니까 재편집하는 기능도 필요해서 넣었고, 공지 이미지 삭제 버튼도 추가했습니다. 

39. 보완 ④ — 더 안전하게: 삭제 · 복구 · 품절

안전장치도 늘렸습니다. 샘플 상품을 삭제하는 기능을 만들었는데 삭제를 누르면 바로 삭제가 되어서 삭제 확인창이 뜨게 만들었고, 지운 상품은 삭제 내역 탭에서 다시 등록할 수 있게 만들었습니다.  체크한 것과 다른 상품이 열리던 버그도 고쳤고, 아까 마지막에 보여드렸던 앱 내에서 품절 처리 기능도 추가했습니다.

40. 배운 점

배운 점은 네 가지입니다. 첫째, 설계도를 먼저 주면 AI가 원하는 결과를 훨씬 정확하게 만듭니다. 둘째, 단계마다 확인하고 넘어가니 문제를 빨리 찾을 수 있었습니다. 셋째, 직접 써 봐야 필요한 기능이 보였습니다. 넷째, 안전장치를 미리 만들어 두면 실수해도 되돌릴 수 있습니다.
